## The problem

[NOVA](https://hypervisor.org/) is an open source microhypervisor, so every build has to be proven on real hardware before anyone can trust it. Qualification meant running suites across **29 hardware configurations and cloud bare metal servers**, with an engineer supervising for hours: kicking off runs, watching for hangs, rerunning flaky jobs and stitching the results together. That is expensive senior time spent on work that follows a predictable pattern, which makes it a strong fit for an agent.

An engineer asks for a test run in Slack the way they would ask a colleague. The agent parses the request into a structured intent, plans which configurations and suites to run, checks the plan against budget guardrails and then fans the work out to the runners. A verification step separates real failures from flaky ones and retries only where a retry can actually change the outcome. The result comes back to the same Slack thread as a readable report.

## Key engineering decisions

<Decision title="Slack as the interface, not a new dashboard">
Engineers already lived in Slack. Natural language command parsing meant **zero onboarding**: anyone on the team could self serve a test run on demand without learning a new tool or waiting for the one person who knew the scripts.
</Decision>

<Decision title="Budget guardrails before execution, not after">
Cloud bare metal is expensive and an agent that loops is a cost incident waiting to happen. Every plan is checked against spend limits **before** any machine is provisioned, so the agent can never burn budget on its own initiative.
</Decision>

<Decision title="Failure aware retries instead of blind reruns">
Blind reruns hide real bugs and waste machine hours. The agent classifies failures first and only retries when the evidence points at flakiness, which **cut cloud spend and reduced flaky reruns**.
</Decision>

## Results

- Multi hour, engineer supervised qualification cycles reduced to **a few minutes**.
- Self serve test runs on demand for the whole team.
- Lower cloud spend and fewer flaky reruns thanks to guardrails and smarter retries.
- Automated AI security scanning added to LLM deployments, replacing periodic manual review with **checks on every build**.

## What I would do next

Feed historical run data back into the planner so it can prioritise the configurations most likely to fail for a given change, and expose the agent's decisions as a trace that reviewers can audit after the fact.
