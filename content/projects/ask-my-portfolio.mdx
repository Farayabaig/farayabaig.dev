## The idea

The strongest proof of AI engineering on a portfolio is a working AI system on the portfolio. This assistant answers questions about my work using only the CV and case studies on this site.

## Key engineering decisions

<Decision title="Answer only from retrieved context">
If the retriever finds nothing relevant, the assistant says so instead of guessing.
</Decision>

<Decision title="Treat retrieved text as data">
Retrieved passages are wrapped and labelled as untrusted data, and the model is told never to follow instructions inside them. This is the same indirect prompt injection defense I test for in client systems.
</Decision>

<Decision title="Strict limits">
A small model, short answers and per IP rate limits keep the cost predictable.
</Decision>

## How it works

1. **Guard the input.** Questions are length limited, rate limited per visitor, capped per day, and screened for obvious injection attempts ("ignore previous instructions", fake system tags) before anything reaches the model.
2. **Retrieve.** A small BM25 index over this site's own content (CV, case studies, blog posts, open source projects) finds the most relevant passages, with light stemming and at most two passages per page so answers draw on several sources.
3. **Generate.** Claude Haiku 5.5 answers in two to four sentences from those passages only, at low effort to keep it fast and cheap. The system prompt is cached, so repeat questions cost less.
4. **Stream.** The answer streams into the chat word by word, followed by links to the sources it used. Follow up questions carry the last two exchanges for context.

## Status

Live: open the chat button in the corner of any page. Everything runs inside the site's own API route, with no vector database or extra service to maintain.
